### Track B — needs a 15–20 min Opus design session before Sonnet implements

| Item | Notes |

| UUIDv4 primary keys should be v7 | Every operational table (`approval_policy`, `audit_event`, `backup`, `divergence_entry`, `export_job`, `orb`, `restore_job`, …) uses `field.UUID("id", uuid.UUID{}).Default(uuid.New)` — that is **UUIDv4, random**. Random keys scatter B-tree inserts across the index instead of appending at the right edge, so pages fragment and the working set grows; time-ordered **UUIDv7** fixes that and gives rough creation ordering for free, which also makes `ORDER BY id` a sane fallback. Current advice (RFC 9562, 2024) is v7 for new database keys; v4 for keys that must not leak a timestamp. **Not urgent** — invisible at orbital's row counts, and it is a schema-wide change, so do it in one pass rather than per table. **Do NOT rewrite existing ids**: v4 and v7 are both valid UUIDs and coexist in one column, so switching the default is enough. `google/uuid` exposes `uuid.NewV7()` (returns an error, unlike `uuid.New`), so the ent `Default` needs a small wrapper that falls back to v4 rather than panicking. ### Architecture — requires design discussion before any code

| Item | Notes |
|---|---|
| Orbital HA — pervasive single-replica assumptions | Deployed `replicas: 1`, `strategy: Recreate`. Divergence ingester (`lastIngestedByDC` in-memory), backup scheduler (cron double-fires), publish-history ingester all assume single-leader. Going HA needs leader election / advisory locks / dedicated ingest deployment. **Do NOT scale past `replicas: 1`** — double-ingestion corrupts divergence state. |
| The graphdiff-rendering surfaces build HTML in JavaScript, not Go templates | **Raised 2026-09-01.** The house pattern is a Go template plus `HX-Request` fragment negotiation inside the existing handler — `audit.go`, `backup.go`, `export.go`, `datacenter.go`, `cluster.go`, `networkdevice.go`, restore-jobs, oci-artifacts and divergence-reports all do it. **Five surfaces do not:** the change-request queue, the change-request review page, export preview, artifact compare, and approval-policies. `grep -n "HX-Request" internal/handler/changerequest*.go` returns nothing — those endpoints are JSON-only with no fragment representation. **This is ONE decision, not five.** The four diff-adjacent surfaces share `renderExportPreviewTable` (three callers: `orbital.js:619` export preview, `:2796` change-request diff, `:3522` artifact compare), all consuming the identical flat `changes[]` a single graphdiff core produces. Server-rendering any one of them needs a Go twin of that renderer or the three drift, so the real question is **"should the graphdiff renderer live in Go"** — answer it once and all four convert together. Do NOT convert a single page, and especially not part of one: splitting a page across both patterns is worse than either. **The framing that made this look principled was wrong.** "API-first — orbital's UI is a consumer of its own API, never a privileged server-rendered path" was read as forbidding server-rendered HTML. It does not: CLAUDE.md's own rule is to branch on `HX-Request` **inside the existing handler**, so the JSON contract is untouched and the fragment is a second representation of the same resource. The two conventions never conflicted. **Two concrete costs, both stronger than the consistency argument.** (1) *The client interprets an authorization decision* — `availableActions` is derived server-side from role, authorship, status and prior approvals, and `actionButtons()` in `orbital.js` loops over it to decide which controls exist. It is faithful today and nothing enforces that it stays so; a fragment makes drift structurally impossible. (2) *Escaping is manual* — every interpolation needs an explicit `esc()`, where a Go template escapes by construction. All current call sites are correct, but titles, descriptions and review comments are now free-form user text flowing through string concatenation. **No user-visible payoff**, which is why it is filed rather than done. |
| Storage and Network panels cannot surface a proposed change at all | **Raised 2026-09-02.** The proposed-change surfaces (banner, field marks, tab dots) all key on `data-field-orbid` + `data-field="<name>"` rows, which only exist on **field/value tables** — Server Summary, iDRAC, Maintenance. Storage and Network panels render **lists of child entities** (a row per device: Name / Manufacturer / Capacity / Serial / WWN), so a change request touching a `StorageDevice` or `NetworkInterface` field shows **nothing anywhere on the server tab** — no mark, no dot, and the top-of-tab banner only counts requests without saying where. A reviewer can therefore retype exactly the edit this feature exists to prevent. **Design call:** mark at ROW level ("this device has a proposal", linking to the request) which needs a per-row orbId and a different mark shape than the field tables use; or tab-dot only, so the tab at least says "look in here" without per-row detail. Lean row-level — a list of 24 storage devices with an undifferentiated tab dot is barely better than nothing. Do NOT bolt `data-field` rows onto a list table to reuse the existing renderer: the field tables are field-per-row and these are entity-per-row, and forcing one shape onto both is how the three tables that "must not drift" start drifting. |
| Change-request `before` guards composite fields at WHOLE-VALUE granularity | **Raised 2026-09-02.** `assertBefore` in `configitem-editor.js` sends **primitives only** (deliberately — an edge value is a `{orbId}` object living elsewhere in the snapshot, so asserting it would compare two shapes). A String field holding JSON *is* a primitive and therefore *is* guarded — but as one opaque value. So two proposers editing **different keys inside `DataCenter.assetDataV2`** collide as a total conflict. No data loss (the guard is correct — it refuses), but it is a **false conflict no amount of re-review resolves**: `base_values` re-anchors to the other party's whole blob, so the only exit is one side rewriting their edit. Not hypothetical — the single-JSON-editor-at-parent pattern (`UI.md`) means owned-child edits land inside exactly this kind of blob. **Design call:** guard sub-keys (parse the JSON and diff per key — leaks blob structure into the engine, and the engine is deliberately store-neutral), or keep whole-value and make the refusal message say *which keys* differ so a human can resolve it by hand (cheaper, no semantics change), or leave it. Lean option 2. Do NOT extend `before` to non-primitives without revisiting why edges were excluded. |
| A changeset cannot distinguish ASSERTED intent from INCIDENTAL fields | **Raised 2026-09-02.** `set` is target end-state, so `set: {a: 1, b: 2}` where `b` was already `2` is indistinguishable from a deliberate assertion of both — the reviewer cannot tell narrow intent from wide. Mitigated for *display* by `satisfied[]` on `GET /{id}/diff` (already-applied fields render struck through), but the mitigation depends on `base_values`: a request whose snapshot read failed, or one created before the ancestor existed, degrades silently to "everything looks proposed" with no marker saying the comparison was unavailable. **Two candidate fixes:** carry an explicit `asserted` flag per field (honest, but a new API concept and every client must set it), or surface `baseValuesAvailable: false` on the diff response so a client can say *"cannot distinguish"* instead of implying it did. Lean the second — it is one boolean and it removes a silent failure rather than adding a concept. Related: `CHANGE-CONTROL.md` § How we arrived at this shape. |
| Auto-apply DGraph GraphQL schema on startup | Today orbital does NOT apply `schema.graphql` on boot, so a schema-bumping image deploy silently drifts until someone POSTs to `/admin/schema` — the 2026-07-27 AKS burn (v0.0.25 queried `retentionDays`, DGraph still v3 → every cluster 404'd). **Proposed:** apply the schema additively on startup, mirroring ent auto-migrate for PostgreSQL. **Design points:** (1) re-scopes the "schema migration out of MVP" decision; (2) blue-green apply to active/blue on boot; (3) additive-only guard; (4) confirm multi-replica racing is harmless (DGraph serializes); (5) fix the `schema.graphql:6` vs `DGRAPH.md` doc contradiction. Alternatives: kustomize initContainer, GitOps PreSync Job. Triggered by the 2026-07-27 burn. |
